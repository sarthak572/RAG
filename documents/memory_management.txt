Memory Management

1. Why Memory Management?
Memory management is responsible for keeping track of each byte in a computer's memory, and
deciding how memory should be allocated among competing processes. The goals are efficient use
of memory, protection between processes, and support for more processes than physically fit in
memory at once.

2. Contiguous Memory Allocation
In contiguous allocation, each process is allocated a single contiguous block of memory.
- Fixed partitioning: memory is divided into fixed-size partitions at system startup, causing
  internal fragmentation (wasted space inside a partition when a process is smaller than it).
- Dynamic partitioning: partitions are created dynamically to exactly fit each process's needs,
  which avoids internal fragmentation but causes external fragmentation (free memory is broken
  into small, scattered, non-contiguous pieces over time).
Allocation strategies for dynamic partitioning include First-fit (allocate the first hole big
enough), Best-fit (allocate the smallest hole big enough, minimizing leftover space but leaving
tiny unusable fragments), and Worst-fit (allocate the largest hole, leaving a large usable
remainder).

3. Paging
Paging solves external fragmentation by allowing a process's physical address space to be
non-contiguous. Physical memory is divided into fixed-size blocks called frames, and logical
memory is divided into blocks of the same size called pages. Every logical address generated by
the CPU is split into a page number (p) and a page offset (d). The page number indexes into a
per-process page table, which stores the base address (frame number) of that page in physical
memory; the offset is combined with the frame's base address to get the actual physical address.
Paging still allows internal fragmentation, on average half a page per process.

4. Translation Lookaside Buffer (TLB)
Because the page table itself resides in memory, a naive page table lookup would double the
memory access time for every reference. The TLB is a small, fast, associative (content-
addressable) hardware cache of recent page-number-to-frame-number translations. On a TLB hit,
translation is essentially free; on a TLB miss, the page table in memory must be consulted and
the result is cached in the TLB for future use. TLB hit ratio is a critical performance factor
in paged systems.

5. Segmentation
Segmentation is a memory management scheme that supports the programmer's view of memory: a
program is a collection of segments, such as the main program, functions, stack, and symbol
table, each of variable length. A logical address consists of a segment number and an offset.
A segment table maps each segment number to its base address and length (limit) in physical
memory, and the hardware checks the offset against the limit to prevent a process from
accessing memory outside its own segment.

6. Virtual Memory
Virtual memory separates a process's logical (virtual) address space from physical memory,
allowing a process to execute even if it is only partially loaded in memory. This allows
programs larger than physical memory to run, increases the degree of multiprogramming (more
processes fit "in memory" because each only needs part of its pages resident), and simplifies
programming since the programmer does not manage overlays manually. Virtual memory is commonly
implemented via demand paging.

7. Demand Paging
Under demand paging, a page is loaded into memory only when it is actually referenced, not in
advance. Each page table entry has a valid/invalid bit. If a process accesses a page marked
invalid (not currently in memory), a page fault trap occurs, and the operating system's page
fault handler: (1) checks whether the reference was valid, (2) finds a free frame (or evicts a
page from an occupied frame), (3) reads the desired page into that frame from disk, (4) updates
the page table, and (5) restarts the instruction that caused the fault.

8. Page Replacement Algorithms
When memory is full and a page fault occurs, an existing page must be evicted to make room.
- FIFO: evicts the page that has been in memory the longest, regardless of usage. Simple to
  implement but can suffer from Belady's Anomaly, where increasing the number of frames
  actually increases the number of page faults for some reference strings.
- Optimal (OPT/MIN): evicts the page that will not be used for the longest time in the future.
  This has the lowest possible page-fault rate of any algorithm, but it requires future
  knowledge of the reference string, so it is used only as a theoretical benchmark to evaluate
  other algorithms, not in real systems.
- Least Recently Used (LRU): evicts the page that has not been used for the longest time in the
  past, using recent history as an approximation of future behavior. LRU does not suffer from
  Belady's Anomaly and generally performs close to Optimal, but exact LRU is expensive to
  implement in hardware (it needs either timestamps on every memory reference or a stack
  update on every reference), so real systems use approximations such as the Clock (Second-
  Chance) algorithm.

9. Thrashing
Thrashing occurs when a process does not have enough frames to hold the pages it is actively
using, causing it to page-fault almost continuously -- it spends more time paging than
executing. This can cascade: as processes thrash, CPU utilization drops, so the OS may
schedule even more processes to raise utilization, worsening the thrashing further. The
working-set model (the set of pages a process is actively referencing in a recent time window)
is used to allocate frames based on a process's actual locality of reference and prevent
thrashing.
